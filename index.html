Objective

This tool captures real packets from a network adapter you are authorised to monitor, and measures observable metadata: packet sizes, ports, timing and the randomness of payload bytes. It gives a heuristic score that describes how closely the traffic pattern resembles typical VPN traffic.

Packet capture

The browser sends the chosen adapter and duration to the server with POST /capture/start and GET /capture/status. The server runs Scapy's sniff() on that adapter for the chosen duration, up to 20,000 packets, then analyses the packets and returns the result. The page polls capture status while the backend captures packets, then displays the final analysis. Capturing needs administrator or root privileges and a packet-capture driver (Npcap on Windows, libpcap on Linux and macOS).

Features

Payload entropy: Shannon entropy of each payload of at least 64 bytes, normalised by the maximum that payload length can reach. Encrypted data looks random, but HTTPS does too, so this is not proof of a VPN.

VPN port matches: the share of TCP and UDP packets that use a well-known VPN default port (1194, 51820, 500, 4500, 1701). VPNs can use any port, so this is only an indicator.

Packet size: mean frame size relative to a reference of 1400 bytes. Many packets are close to that size, so this feature is weak.

Timing regularity: the coefficient of variation of gaps between packets across the whole capture. This is not per-flow timing.

Scoring

score = 45 × entropy + 35 × vpn_port + 10 × packet_size + 10 × timing_regularity

Each feature is between 0 and 1, so the score is between 0 and 100. The weights and thresholds (VPN-like at 60 or above, normal-like at 40 or below) are manually chosen heuristic parameters. They are not calibrated on data and must be evaluated with labelled experiments.

Inconclusive results

The result is inconclusive when there are fewer than 50 packets, fewer than 20 payload samples, or a score between the two thresholds.

Traffic graph

The graph counts captured packets in one-second buckets, starting from the first captured packet. It is drawn after the capture finishes and is not a live stream.

Experiments

After each capture, the classifier automatically assigns "Normal-like", "VPN-like" or "Inconclusive" and saves the summary. These are heuristic predictions, not proof of VPN use. Saved runs are stored locally as summary numbers only, and can be exported to CSV.

Limitations: HTTPS and other encrypted traffic can look like VPN traffic, and VPN traffic can look like normal traffic. The score is not a probability and does not prove that a VPN is in use. Results depend on the adapter chosen: a physical adapter and a VPN virtual adapter show different packets.
Privacy: only packet metadata is used. Payloads are never decrypted or saved, and IP addresses are not displayed or stored.

What this project is

A local web application that captures live packets from a Wi-Fi or Ethernet adapter and analyses their metadata to suggest whether the traffic pattern looks like VPN traffic. It is a heuristic lab tool for a cyber security project, not a VPN or anonymity detector.

Technologies

Python, Flask (web server), Scapy (packet capture), HTML, CSS and vanilla JavaScript. Charts are drawn with plain SVG, so there are no external chart libraries.

How to run (Windows)

1. Install Npcap. It comes with Wireshark, or can be installed separately.
2. Open the project folder in a terminal run as Administrator.
3. Run pip install -r requirements.txt, then python app.py.
4. Open http://127.0.0.1:5000 in your browser.

Authorised use

Capture only on your own machine and on networks you are allowed to monitor. The tool does not decrypt traffic, collect credentials, or store payloads.

Tor exit-node matching is included as a supplementary analysis. It reports packet match counts only; it does not prove Tor Browser usage.
